### A-2b. 图片插入（`test-dom-smoke.mjs` 4 项 + `test-app-wiring.mjs` 5 项 + 页面内自检 1 项）

| 验的是什么 | 断言 |
| --- | --- |
| 四个位置都放对 | `before`/`after` 插成兄弟、`append`/`prepend` 插进内部；不写 `position` 默认 `append` |
| 资源校验 | id 不存在 → `E_PATCH_UNKNOWN_ASSET`（消息里列出可用 id）；没带图 → 同样报错；非图片 data URL → `E_PATCH_BAD_ASSET` |
| 样式收窄白名单 | `width`/`border-radius` 写入；`url(...)` 值丢弃；`position:fixed`、`z-index` 丢弃（不许把图拽出文档流盖住整页） |
| 范围约束 | 允许"插进选区内部的嵌套容器"（选中整块、把图放到里面某个标题下面）；插到选区之外整单拒绝且 DOM 零改动 |
| 撤销 | 撤销后精确摘掉图片、不留残渣（`.hero` 里的兄弟关系不变） |
| 上下文只给元数据 | `context.assets` 有 id/名称/尺寸/体积；**整份上下文里不出现 base64** |
| 图片单独传给模型 | `provider.generate(context, { assets })` 拿到 data URL（供视觉模型）；关掉"让模型看图"后不再传 |
| 自愈 | 模型写了不存在的图片 id → 自动重试一次，并把可用 id 回喂给模型 |
| 端到端 | 贴图 + "放在标题下面" → 图片真的插进 iframe DOM，`src` 是父窗口补的真实 data URL；发送后待发送区清空；接受后撤销能摘掉 |
| 离线引擎 | 带图且说方位词时，Mock 也按"下面/上面/里面/当背景"给出对应操作（离线可演示、可测） |
| 背景图 | `setBackgroundImage` 设 `background-image` + size/position/repeat；**不插入 `<img>`**；撤销后 `style` 逐字节复原；非法 size / 不存在的资源 / 非图片 data URL 全部拦住 |
| 背景端到端 | 贴图 + "把这张图当这一页的背景" → 选中区块的 `background-image` 被设为内嵌 data URL，页面里**没有新增 `<img>`** |
| 代理体积 | 本地代理 `MAX_BODY` ≥ 8MB 且超限回 413（`test-bundle` 守着；实测 1.13MB → 200、12.9MB → 413） |
| 粘性降级 | 模型拒绝图片输入后记住（`visionBlocked`），后续请求不再上传图片（每次省 ~1MB），但图片仍会用于插入 |


### A-2. 交互隔离（`test-app-wiring.mjs` 3 项 + 页面内自检 1 项）

用一份"类 PPT"夹具复刻真实场景：页面把**左键翻页绑在容器**上（冒泡）、把**方向键翻页绑在 `window`** 上（冒泡），
还额外绑了一个 `document` 级监听（最难挡的一种）。

| 验的是什么 | 断言 |
| --- | --- |
| 指代器开启 → 页面被冻住 | 夹具的三个监听（容器 / `document` / `window`）**全部不触发**，页面状态不被改动 |
| 指代器开启 → 指代器自己照常工作 | 隔离层在场时悬停仍能命中页面元素（走 `elementsFromPoint` 跳过隔离层），高亮有名字 |
| 指代器关闭 → 页面完全恢复 | 三个监听**全部正常触发**、页面状态真的改变；隔离层被撤掉；桥切到 `browse` |
| 再开回来 | 隔离层重新铺上，页面立刻又收不到输入 |
| 键盘被冻住但快捷键可用 | `Ctrl+Z` / `Ctrl+Shift+Z` / `Ctrl+S` 被转发成 `undo` / `redo` / `save`；页面仍然收不到方向键 |

### A1. Patch 契约与护栏（`test-unit.mjs`，32 项）

| 验的是什么 | 对应验收标准 |
| --- | --- |
| 合法 Patch v1 接受；空 changes / 非数组 / 未知 op 拒绝 | 结构化输出契约 |
| `!important` 被拆到 priority | 执行器语义 |
| `data-pid` / `on*` / `style` / `srcdoc` / `data-z-*` 属性一律拒绝 | **AI 不许改锚点** |
| **属性值也要过 URL 白名单**：`href="javascript:…"` / `src="data:text/html,…"` 被拒 | 只校验属性名是不够的 |
| 样式属性白名单拦住野属性；`16px; color:red` 这类注入被拒 | 不许越界改样式 |
| `validatePatchScope` 拦住范围外 target | **只改选中范围** |
| 超过 50 条改动被拒 | 防整页重写 |
| 裸数组 / 单条 op / `operations` / `edits` 字段容错 | 模型输出容错 |
| **纯 HTML 回复直接报错**（绝不当作可执行内容） | 不接 HTML 字符串 |
| Mock 规则引擎 12 类指令输出**全部通过校验** | 离线链路不翻车 |
| 快照栈：逐级撤销/重做、撤销后 push 砍未来分支、jumpTo 任意版本、超上限丢最老但保初始版、持久化恢复、工程导入导出 | **接受 = 一个快照 / 撤销重做 / 历史回看** |

### A2. 真实 DOM 链路（`test-dom-smoke.mjs`，24 项）

用最小 DOM 实现（`tools/dom-shim.mjs`，不进产物）跑真实执行路径：

| 验的是什么 | 说明 |
| --- | --- |
| 全量注入后**所有元素**都有唯一 pid | 锚点完整性 |
| **同一份 HTML 两次解析得到同一套 pid** | 锚点可复现（跨会话稳定） |
| pick → context → patch → **预览** → **取消后逐字节还原** | 第 2 步验收 |
| 越界改动被拒且 DOM 零改动 | 范围硬边界 |
| **事务性**：改动中途出错时，前面已应用的改动必须回滚 | "要么全改、要么一点都不改" |
| 同一 patch 里删掉选中元素后再改它 → 明确报越界（不是内部错误）且回滚 | 边界语义清晰 |
| 锚点保护：`setAttr(data-pid)` 被拒 | 锚点不可篡改 |
| 脚本被剥离；`setHtml` 后新节点自动补锚点 | 安全 + 锚点不丢 |
| `insertHtml` / `removeNode` 撤销后完全还原 | 撤销精确性 |
| **撤销后 pid 不漂移**、`resolve(pid)` 命中同一元素、DOM 无重复 pid | 验收标准 4 的前提 |
| 干净导出：无 pid / 无选中类 / 无编辑器注入，改动保留 | 导出即成品 |
| **插入纯文本/混合内容的撤销必须逐字节还原**（含文本节点） | 取消精确性 |
| **撤销不重算 pid**：插入/删除兄弟后再改再撤销，锚点不漂 | 锚点稳定 |
| `insertHtml` 落点边界：留在选区内允许，改到祖先层拒绝 | 范围硬约束 |
| 用户 HTML 自带重复 `data-pid` 会被修复为唯一锚点 | 锚点唯一 |
| 同一 patch 内删掉选中元素后再改它 → 明确报越界且回滚 | 边界语义 |
| **`<style>` 与 `data-z-*` 必须被剥离**（否则绕过"只改选中块"/内容在快照里消失） | 安全 + 交付物完整性 |
| **不允许删除 `<html>`**（没有可还原的父元素快照） | 防页面报废 |
| **撤销不会吃掉正文里形如 ` data-pid=…` 的文字** | 撤销不许丢字 |
| **注入的 bootstrap `<script data-z-inject>` 必须被剥掉**；且"先注入锚点再清洁"与"从未注入"结果等价 | 成品里不许残留编辑器代码 |
| `sanitizeHtmlFragment` 拦掉 `<script>` / `onclick` / `javascript:` | 安全边界 |

### A3. 打包产物与接线契约（`test-bundle.mjs`，9 项）

| 验的是什么 |
| --- |
| 产物比源码新（防"改了代码没重新构建"的假通过） |
| **契约：`app.mjs` 调用的每个 `rpc('op')` 都必须真实存在于 bridge 能力表**（见下方 bug #9） |

| 桥 bundle 能在 DOM 桩上安装并暴露 `injectAnchors / select / getContext / applyPatch / undoPatch / …` |

| 单文件 HTML 自包含：无外链 script/style，样式、示例页、桥源码全部内联 |

### A5. 构建期硬失败（不再"构建成功、运行即坏"）

- **依赖闭合校验**：漏模块 / 顺序错 → 构建直接失败，而不是打开页面白屏。
- **不支持的 import/export 写法直接抛错**：`import './x'`、`import {a as b}`、`import * as ns`、
  `import def, {a}`、`export default` 都会让构建失败并给出说明（早期版本会静默生成坏代码）。
- 再导出 `export {a} from './x'` 用 `exports[k] ??= …`，避免被同名本地声明顶掉。

## C. 已知边界（不算通过，是交代）

| 边界 | 影响 | 应对 |
| --- | --- | --- |
| 无头浏览器不可用 | 真浏览器端到端未跑 | 用 B1 页面内自检 + A0 应用级接线测试代替；`tools/test-e2e.mjs` 保留，环境允许时可直接跑 |
| **同源 iframe 的隔离是"防误伤"，不是"防恶意"** | http 页面下 iframe 与编辑器同源，用户页面里的脚本理论上能访问父窗口；`file://` 下为了可用性干脆不加 sandbox | 只编辑你信任的 HTML；要跑不可信页面就先在隔离环境里做。详见 [REVIEW.md](REVIEW.md) S6 |
| 直接填 API key 时会留在页面内存里 | 同源脚本理论上可读 | 推荐用 `tools/serve.mjs` 的本地代理模式：key 只在 Node 侧，浏览器里没有 key（key 已不再写入 localStorage） |
| 跨域样式表读不到 `cssRules` | 模型少看到这部分规则 | 计算样式仍准确，改动仍可用 |
| localStorage 4 MB / 40 版上限 | 极端情况丢最老版本（初始版永不丢） | 会提示导出；重要工作用"导出工程" |
| 属性顺序差异 | "逐字节还原"用的是 outerHTML 字符串比较；极端情况下属性顺序可能与原始不同（语义等价） | 语义等价即视为还原；断言以"内容+取值"为准 |

## D. 回归建议（改代码之后）

```powershell
node tools/build.mjs && node tools/test-unit.mjs && node tools/test-dom-smoke.mjs && node tools/test-app-wiring.mjs && node tools/test-bundle.mjs
```

五项都必须绿。**改了 `app.mjs` / `bridge.mjs` 的任何交互，必须跑 `test-app-wiring`**——
它是唯一能发现"模块都对、接线全错"的测试。

历史上抓到的真 bug（按严重度）：

1. **父窗口从未注册 `message` 监听**（`onWindowMessage` 是死代码）→ `iframeReady` 永不 resolve
   → `ensureBridge`/`rpc` 永久挂起 → **编辑器在浏览器里根本起不来**；
2. **桥被 `(0,eval)` 装进了父窗口自己的 `document`**（不是 iframe）→ 指代器与补丁作用在编辑器 UI 上，
   导出会把编辑器界面当用户页面；
3. **RPC 参数形状不一致**：桥的 `select: (pid)` 收字符串、`applyPatch: (patch)` 收裸 patch，
   而调用方发 `{pid}` / `{patch}` → `resolve('[object Object]')` 永远失败 → **选中与预览整条链是坏的**；
   （上面 1–3 都是"模块全绿但应用不可用"的典型，现在由 `test-app-wiring.mjs` 常驻拦住）
4. 接线错误：`app.mjs` 调 `rpc('extractHtml')`，而桥里只有 `extractCleanHtml` → 主流程抛 `E_NO_OP`；
5. `extractCleanHtml` 只删 `data-z-chrome`、忘了 `data-z-inject` → 每个快照与导出里都残留编辑器注入脚本；
6. `insertHtml` 在注入锚点**之前**记录 pid → 逆操作拿到 `null` → 撤销删不掉插入的节点；
7. 撤销只回填 `innerHTML`、**不还原属性** → `setStyle` 的改动留在元素上；
8. 快照里**带着旧 `data-pid`** → 还原后出现重复锚点 → `resolve(pid)` 命中错误元素；
9. `ensure()` 把**已不在 DOM 里的旧 pid** 当冲突 → 还原后 pid 漂移成 `p-xxx-1`；
10. 撤销时**重算 pid**（而不是用快照记录的 pid）→ 结构变更后锚点漂移；
11. **纯文本 `insertHtml` 撤销后残留**（逆操作只收集元素节点）→ "取消=逐字节还原"不成立；
12. 执行器信任外部元素引用 → 引用悬空（撤销后）时范围判断误判；
13. 中途校验失败**不回滚** → 留下"改了一半"的页面；
14. 同一 patch 内删掉选中元素后再改它 → 抛内部错误而不是明确的越界拒绝；
15. `setAttr` **只校验属性名不校验值** → `href="javascript:…"` 能写进 DOM；
16. `sanitize` 放行 `<style>` → 一次 `setHtml` 就能给整页注入全局 CSS；
17. `sanitize` 放行 `data-z-*` 属性，而导出时带该属性的元素被整块删除 → **用户接受的内容在快照里消失**；
18. `removeNode` 允许删除 `<html>` → 没有可还原的父元素快照，页面报废且撤销静默跳过；
19. `stripPids` 用正则全局删除 ` data-pid=…` → 连正文里的同样文字一起吃掉，撤销永久丢字；
20. Mock 颜色匹配顺序错误（"浅蓝"被"蓝"截胡）。

> 测试基础设施（`tools/dom-shim.mjs`）自身也修了多个失真点，否则它会制造假问题或放过真问题：
> `hasAttribute('style')` 恒为 false、`el.style` 与 `style` 属性两份状态不同步、
> 脚本执行时机早于文本子节点挂载、缺 `window` 自引用与定时器、以及——最关键——补上 iframe realm
> （独立 vm 上下文 + postMessage 投递），否则根本没法在 Node 里验证应用接线。
